# F1 — LOCAL Windows/WSL2 + Docker + real synthetic Supabase (8 steps)

**Purpose:** One reproducible LOCAL guide, NOT a claim that the PO's Windows host works. Use a fresh folder, never an existing dirty checkout/worktree. No hosted keys, data, secrets, or paid services.

1. **Create an isolated copy** in Windows PowerShell from a parent directory with no existing folder named atlas-f1-pr26:
   `git clone --single-branch -b feature/platform-foundation-f1-f3-20261122-builder https://github.com/OgerFurkan/yds-atlas-pro.git atlas-f1-pr26`
   Then `cd atlas-f1-pr26` and `git status --porcelain` (must be empty). Do not clean, reset, stash, or prune other existing checkouts.
2. **Check physical prerequisites** from that folder: `wsl --status`, `docker context show`, `docker info`, `bun --version` (required **1.3.5**), `node --version` (>=20). In Docker Desktop enable WSL2 backend + integration to the chosen distro; context must be the local Docker daemon. If Docker is missing, remote, or unavailable: **STOP/BLOCKED**, no installation claimed.
3. **Frozen dependency + tool check**, repository root: `bun install --frozen-lockfile`, `node scripts/local/preflight.mjs`, `bunx supabase --help`. Every preflight line must PASS; any mismatch is **STOP**, no attempt to link to staging/prod.
4. **Start LOCAL PG17/Auth only**, repository root: `bunx supabase start`, followed by `bunx supabase status -o json` (do NOT paste CLI JSON into chat/CI; it may contain local keys). Inspect the selected Docker context/volume and ensure LOCAL service is at 127.0.0.1:54321; no `supabase link` or cloud operations. Do not run db reset by default; it requires explicit proof the volume is disposable.
5. **Two real synthetic LOCAL GoTrue sessions and RLS**, same PowerShell session/root: load the **LOCAL** anon/publishable key into shell variable ONLY (`$localStatus = bunx supabase status -o json | ConvertFrom-Json; $env:LOCAL_SUPABASE_ANON_KEY = $localStatus.ANON_KEY`); do not print or commit it. Execute `node --test scripts/local/target-guard.test.mjs` and `node scripts/local/supabase-tenant-smoke.mjs`. Expect cross-owner SELECT/UPDATE/DELETE/forged INSERT and anon/RPC negative PASS; any error is **FAIL/BLOCKED**. This checks LOCAL real JWT/PostgREST, not staging.
6. **Unit, Vite, browser and code gates** from repository root: `bun run format:check`, `bun run lint`, `bun run build`, `bun test backend/tests frontend/tests/unit`, `node scripts/quality/foundation-contract.mjs`. Install browsers in frontend with `cd frontend; bunx playwright install chromium firefox webkit; cd ..`, then from root `bun run --cwd=frontend test:e2e` and in frontend `bunx playwright test --config playwright.qa.config.ts`. For any FAIL, preserve logs, do not call that suite PASS.
7. **LOCAL Render/Bun Docker validation**, repository root: only after reviewing disk/daemon and ensuring test tag/container ID is unused, `docker build -f backend/Dockerfile -t atlas-f1-local-api .`. Start with `docker run -d --network none -e HOST=127.0.0.1 -e PORT=3000 atlas-f1-local-api` (record returned container ID; no port publication). Inspect inside **that container only** using `docker exec <container-id> bun -e "fetch('http://127.0.0.1:3000/api/health').then(r=>{if(!r.ok)process.exit(1);console.log(r.status)})"`. The returned 200 is *liveness*, **not DB readiness**. Stop only that ID via `docker stop <container-id>`; no Docker prune/reset.
8. **Stop the LOCAL stack only**, repository root: consult `bunx supabase stop --help`, then `bunx supabase stop` if the containers belong solely to this test. Remove local shell variable `Remove-Item Env:LOCAL_SUPABASE_ANON_KEY`. No cloud service or data should be touched. Preserve all output as user-machine evidence for PM; don't send key/PII/raw DB rows.
